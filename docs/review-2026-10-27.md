# Workspace and interface review — 27 October 2026

## Implemented

- Shared navy, gold and neutral colors across the administration workspace, including dark mode, public catalog, tracking and login. No additional UI dependency was introduced; administration icons now use the existing local Font Awesome package.
- Native checkbox and radio spacing for both languages, with grouped navigation settings, visible focus and mobile spacing.
- Connected workspace navigation: imports → trips → shipments → shipping accounts → messages. The overview links directly to missing financial details, phone/consent review, failed operation messages and pending factory/catalog reviews.
- Trip, shipment and merchant pages link to related accounts, movements, bills and notifications. Message cards link back to their actual shipment or voucher source; missing sources no longer produce a bill link to a deleted shipment.
- Message filters support trip shipment notifications, one shipment, one merchant, one voucher import or one shipment import. Source type is checked alongside source ID, and filters intersect. A phone conversation intentionally opens all messages for that phone so replies are not restricted to an import.
- Shipment uploads return to their own imported shipments. Recent shipment imports appear alongside the voucher import history. Confirmed voucher operations remain visible from persisted vouchers after temporary preview payload removal.
- Manually entered and standalone shipments can prepare one notification from their edit page. Preparation reuses the existing notification, while actual sending retains template, consent, source-version and provider checks.
- Creating a shipment inside a trip uses the actual trip stage. Detaching retains the current trip stage and route; moving to a different trip follows that trip. Existing trip associations are preserved when an update does not submit a trip field.
- The legacy event endpoint now enforces the next stage transactionally. It cannot skip stages or change linked shipments independently; deletion cannot remove the event representing the current stage.
- Legacy content deletion now requires DELETE and CSRF rather than a GET link. The confirmation UI works with the existing dialog library or native confirmation, and failed HTTP responses are not presented as successful deletions.
- Callback forms only show success after a successful server response explicitly confirms persistence. Failed validation no longer displays a thank-you message.
- Light entrance/reveal effects, button feedback and submission indicators; reduced-motion preferences are respected. Native browser history restoration releases buttons disabled by a prior submission.
- Arabic and English client guide instructions were updated without changing chapter identifiers.

## Remaining prerequisites and scope

- WhatsApp is currently disconnected. Live automatic messages and replies require the official service connection, verified templates, recipient consent, public signed webhook reception and an active queue worker/scheduler. Source account summaries and operation notifications remain separate sending workflows.
- Combined purchases-and-shipping balances still require a confirmed opening balance per merchant and currency and an agreed rule preventing double counting between shipment collections and imported receipts. Current pages deliberately keep purchase movements separate from shipping accounts.
- Factory password recovery remains administrator-assisted, as documented in the guide. An email-based reset flow needs a configured mail service. Factory accounts remain separate from administrator accounts; no public merchant login or shopping checkout was added.
- Retention behavior remains intact: original imports are not saved, temporary previews expire, catalog images are resized/compressed, and required financial rows and message identifiers remain available. This review does not delete financial history.
